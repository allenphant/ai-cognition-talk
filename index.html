否 是 是 否
KNOWN UNKNOWNS

我知道我不知道

我知道自己有問題或知識缺口，但不知道答案、方法或判準。

「我隱約覺得境外土壤被直接販賣好像怪怪的，但我說不出哪裡怪。」

Scene 05

一段 Prompt 搭配任意模型，即可擴展認知

這段 Prompt 的價值不是替我們產生唯一正解，
而是協助我們看見原本沒有問出的角度與問題。

  1. 確認背景
  2. 拆解問題
  3. 打破盲點
  4. 列出啟動步驟
▶ 網頁示範

↑ ↓ 可捲動右側 Prompt

你是我的新領域老師與學習引導教練，請分析我接下來提供的圖片、專案、Git repository、 網站、工具或服務，盡可能打破我的訊息繭房，提供該領域內的完整視野。禁止阿諛奉承。 我的領域背景：<輸入你的背景> 我在這個領域的程度和現有認知：<輸入你對這個領域已知的觀察> 你的任務是透過白話解釋、提問、反問與候選問題， 幫助我察覺「我知道什麼、我不知道什麼，以及我可能沒有想到什麼」。 每個專有名詞第一次出現時，請解釋中文意思、英文／縮寫、用途與簡單例子。 請依照以下流程進行： 1. 先用白話說明這個對象可能是什麼、解決什麼問題、如何運作。 分開標示：已確認、推測、未知。 2. 請先問我幾個問題搭配可能的實際案例，引導我自己辨認： - 我能直接說出哪些觀察？ - 哪些地方我知道自己不了解？ - 哪些判斷可能來自我的經驗或直覺，但我還說不清楚？ - 如果要使用、修改或維護它，還有哪些問題是我完全沒想到的？ 3. 根據我的回答，再依照我的視角幫我整理我可能的四種認知狀態： - 已知的已知：我能說明，也能提出依據的內容。 - 已知的未知：我知道自己不懂，或明確知道還缺少的資訊。 - 未知的已知：我可能已有經驗或直覺，但尚未說成清楚的規則。 - 未知的未知：目前尚未想到，但可能影響目標、操作、成本、維護或資安的候選問題。 後兩類只能使用「可能」「候選」「需要確認」， 不可以直接宣稱我已經知道，或宣稱你已經發現真相。 4. 請指出目前最適合的認知狀態轉換： - 如果我以為自己知道：請挑戰假設、找反例。 - 如果我知道自己不知道：請教學、示範並提供檢查表。 - 如果我有直覺但說不清楚：請用反問把經驗整理出來。 - 如果我根本沒想到這個問題：請提出候選盲點，讓我判斷是否相關。 每次都請分開說明： - AI 可以協助什麼 - 我需要自己確認或完成什麼 5. 如果我要開始上手，請從低風險的小練習開始， 告訴我具體要開什麼、點哪裡、下載什麼、輸入什麼， 以及如何判斷成功，怎樣算做失敗。 每個階段都必須說明資安： 資料是否敏感、是否上傳雲端、需要哪些權限或憑證， 是否有惡意檔案、Prompt Injection 或工具濫權風險， 以及如何人工批准、停止與回復。

Scene 06

同一句「幫我下載影片」，AI 到底能做到哪一步？

使用者：我想下載這支 YouTube 影片，要怎麼做？　　目標：取得影片檔案，並放在可回報的位置。

LAYER 1

單次 LLM

只能根據這次輸入產生文字

LAYER 2

Context

外層把前面對話重新放進輸入

LAYER 3

Agent

外層接上工具與控制迴圈，依本機回報決定下一步

Agent最簡化結構

  • LLM

    大腦。讀懂目標、判斷下一步該做什麼、決定什麼時候停 —— 它只產生決定，不動手。

  • Context

    工作桌。每一次呼叫時，把目標、先前對話與工具回報一起攤在桌上 —— LLM 只看得到桌上有的東西。

  • Tools

    眼睛與手。負責看見與動作外部世界：讀檔、寫檔、改檔、執行終端機指令。

  • Harness

    馬鞍與韁繩。把大腦接到工具上：執行工具、把結果送回去、決定下一步，並在該停的地方要求你批准或直接停止。

完整流程｜使用者 · agent · LLM · 本機環境 · YouTube

Scene 12　案例二

同一個「AI 會議紀錄」，可以是三種完全不同的東西

「今天討論：下週完成測試，請小王整理資料，週五前回報。」

  1. 錄音
  2. 語音轉文字
  3. 逐字稿／摘要

AI 負責理解與生成文字。
輸入輸出固定，沒有規劃與工具選擇。

B

Workflow

  1. 錄音
  2. 語音轉文字
  3. 講者分離
  4. 摘要
  5. 固定格式文件

步驟預先寫好，每次照流程執行。
不一定比較弱，只是每一步都先被設計好了。

C

Agent

  1. 理解會議
  2. 查詢行事曆／專案系統
  3. 建立任務
  4. 寄出摘要
  5. 追蹤回覆

AI 需要決定下一步，並呼叫外部工具。
預設有人工作為批准閘門。

讀取資料寫入任務寄送訊息人工批准

多模態描述 AI 能理解什麼；Agentic 描述 AI 能不能決定下一步。差別不只在聰明多少，而在它取得什麼資料、能寫入什麼系統、誰為錯誤負責。

Scene 16

我希望大家站在開悟之坡的起點

既然今天的主題是認知，那我們不妨再往裡面走一點，來認知一下我們自己的認知過程。

起點

還沒有真正進入一個領域，覺得陌生、危險，甚至認為和自己無關。

「AI 一直冒出新名詞、新工具，我看不懂。」
「我不會寫程式，AI 應該跟我沒關係。」
「聽起來很危險，我不應該去碰。」
愚昧之巔

第一次成功帶來大量信心，但還沒看見背後的複雜度與限制。

「AI 可以超快做出我想像中的東西。」
「我是不是可以取代工程師？」
「我是不是可以取代設計師？」
絕望之谷

開始遇到真實世界的錯誤、比較、維護與責任。

「我想做的東西早就有人做過，而且做得比我好。」
「原來還有部署、資安、權限、測試和維護。」
「AI 做出來的東西有點不對，但我不知道怎麼修。」
開悟之坡

信心不再來自一次成功，而是來自方法、驗證與知道何時求助。

「我不需要追完每一個新工具。」
「我開始知道要先問：它解決什麼問題？」
「我做得出原型，但知道原型不等於產品。」
「我可以使用 AI，但不把判斷責任交給 AI。」
平穩高原

AI 不再是魔法，而是可以穩定使用、評估與管理的工具之一。

「我知道什麼時候該用 AI，也知道什麼時候不該用。」
「我能穩定設計、驗證、維護，也知道結果由誰負責。」
做小一點資料不要敏感結果要能人工檢查失敗要能回復 最簡單的開始方式：CDC 給的 Gemini Pro ＋ Canvas
AI 超充站　加快資訊吸收
AI 社團　交流問題、展示作品、互相校準

不要把未經核准的機密資料，直接丟給雲端 AI 模型。
