Scene 04

你知道自己不知道什麼嗎？

這不是能力排名，也不是人格分類，而是針對某一個問題的暫時狀態。

我是否知道自己掌握或缺少？　否 ← → 是
KNOWN UNKNOWNS

我知道我不知道

我知道自己有問題或知識缺口，但不知道答案、方法或判準。

「我隱約覺得境外土壤被直接販賣好像怪怪的，但我說不出哪裡怪。」

AI：解釋概念、示範判斷方法、提供檢查清單與查證來源

KNOWN KNOWNS

我知道我知道

我知道這件事，也知道自己掌握了哪些內容。

「我因為生物學背景看出仙人掌不能被關在密閉空間。」

AI：整理已知、比較方案、產生草稿——加速產出，不代表已替我驗證前提

UNKNOWN UNKNOWNS

我不知道我不知道

我甚至還沒有想到這是一個可以問的問題。

「我完全沒想到，黃黑配色是警示用途，不適合當商品標籤。」

AI：從其他專業提出候選問題、挑戰假設——只是候選，不是真相

UNKNOWN KNOWNS

我不知道我其實知道

我有經驗、直覺或隱性判斷，但還沒把它說清楚。

「我知道這個價錢對我沒有吸引力，但不知道是因為它沒有打折。」

AI：反問把經驗說出來、拆成觀察項目與 SOP——不是替我發明經驗

我是否真的掌握這項知識？　否 ← → 是

Known Unknowns → Known Knowns

AI 教學、示範、比較、建立檢查表。
人要補上：實際套用、比較結果並查證。

Unknown Knowns → Known Knowns

AI 訪談、反問、整理、外顯化。
人要補上：確認清單真的符合專業經驗。

Unknown Unknowns → Known Unknowns

AI 跨域提示、角色切換、問題生成。
人要補上：判斷問題是否合理，決定是否查證。

Scene 05

一段 Prompt 搭配任意模型，即可擴展認知

這段 Prompt 的價值不是替我們產生唯一正解，
而是協助我們看見原本沒有問出的角度與問題。

它會把回答拆成「已確認／推測／未知」，
再用四種認知狀態整理，最後給出可照著做的低風險步驟與資安檢查。

▶ 示範提示
切到準備好的 Gemini 對話紀錄，走一次實際輸出。
回來後接：輸出裡的「上手指南」會給可執行的 code —— 這裡插入對話式 AI 與 AI Agent 的差別。

↑ ↓ 可捲動右側 Prompt

你是我的老師與實作教練 請把我當15歲的初學者。 請分析我提供的圖片、專案、Git repository、網站、工具或服務。 我的領域背景是OOO。 每個專有名詞第一次出現時，請用白話解釋：中文意思、英文／縮寫、用途，以及一個簡單例子。不要只丟專業名詞。 請依序回答： 1.它是什麼、解決什麼問題、如何運作？ 請分開標示：已從提供的資料確認、你的推測、未知的部份。 2.請用以下四類整理： a.已知的已知 - 只列出我已明確提供，或資料可以直接確認的資訊。 - 每項附上判斷依據。 b.已知的未知 - 列出我已經表示不知道，或目前明確缺少的資訊。 - 說明為什麼重要，以及如何查證。 c.未知的已知 - 只列出從我的描述中推測，可能存在但尚未說清楚的經驗、需求或判斷。 - 每項都必須使用「可能」或「需要確認」的說法， - 並改寫成可以問我的問題。 - 不能直接說我已經知道它。 d.未知的未知 - 列出目前沒有被提出，但可能影響目標、操作、成本、維護或資安的候選問題。 - 這些只是待檢查的盲點，不是事實。 - 請說明為什麼值得注意，以及如何驗證。 如果沒有足夠證據，請寫「目前無法判定」，不要自行補完。 3.如果我要開始上手，請從最簡單、低風險的方式開始， 列出可以照著做的階段步驟。每一步請說明： - 要開啟或下載什麼 - 要點擊或輸入什麼 - 預期看到什麼 - 如何判斷成功 - 失敗時如何處理 - 可以做什麼小型練習專案 4.每個階段都必須特別說明資安： - 資料是否敏感 - 是否會上傳雲端 - 需要哪些權限、帳號或憑證 - 是否有惡意檔案、Prompt Injection 或工具濫權風險 - 如何去識別化、人工批准、停止與回復 - 不要把本地、免費或開源直接當成安全。 5.最後告訴我： - 現在可以立刻做的第一步 - 完成後應該得到什麼成果 - 開始前最需要注意的資安事項 如果缺少作業系統、資料來源、權限或目標， 只詢問必要問題；不要自行猜測，也不要一開始就推薦複雜的 API、Agent 或自動化。

Scene 06

同一句「幫我下載影片」，AI 到底能做到哪一步？

使用者：我想下載這支 YouTube 影片，要怎麼做？　　目標：取得影片檔案，並放在可回報的位置。

LAYER 1

單次 LLM

只能根據這次輸入產生文字

LAYER 2

Context

外層把前面對話重新放進輸入

LAYER 3

Tool Call

LLM 提出結構化命令，外層執行器呼叫工具

LAYER 4

ReAct

根據每次 Observation 持續決定下一步

Agent ＝ LLM ＋ Context／狀態 ＋ 工具介面與外層執行器 ＋ ReAct 或其他控制迴圈 ＋ 權限／人工批准 ＋ 結果驗證／停止條件
Agent 不是另一個神奇模型，而是把 LLM 接上狀態、工具、環境與控制迴圈後形成的系統。

Scene 12　案例二

同一個「AI 會議紀錄」，可以是三種完全不同的東西

「今天討論：下週完成測試，請小王整理資料，週五前回報。」

A

模型

  1. 錄音
  2. 語音轉文字
  3. 逐字稿／摘要

AI 負責理解與生成文字。
輸入輸出固定，沒有規劃與工具選擇。

B

Workflow

  1. 錄音
  2. 語音轉文字
  3. 講者分離
  4. 摘要
  5. 固定格式文件

步驟預先寫好，每次照流程執行。
不一定比較弱，只是每一步都先被設計好了。

C

Agent

  1. 理解會議
  2. 查詢行事曆／專案系統
  3. 建立任務
  4. 寄出摘要
  5. 追蹤回覆

AI 需要決定下一步，並呼叫外部工具。
預設有人工作為批准閘門。

讀取資料寫入任務寄送訊息人工批准

多模態描述 AI 能理解什麼；Agentic 描述 AI 能不能決定下一步。差別不只在聰明多少，而在它取得什麼資料、能寫入什麼系統、誰為錯誤負責。

Scene 16

我希望大家站在開悟之坡的起點

既然今天的主題是認知，那我們不妨再往裡面走一點，來認知一下我們自己的認知過程。

起點

還沒有真正進入一個領域，覺得陌生、危險，甚至認為和自己無關。

「AI 一直冒出新名詞、新工具，我看不懂。」
「我不會寫程式，AI 應該跟我沒關係。」
「聽起來很危險，我不應該去碰。」
愚昧之巔

第一次成功帶來大量信心，但還沒看見背後的複雜度與限制。

「AI 可以超快做出我想像中的東西。」
「我是不是可以取代工程師？」
「我是不是可以取代設計師？」
絕望之谷

開始遇到真實世界的錯誤、比較、維護與責任。

「我想做的東西早就有人做過，而且做得比我好。」
「原來還有部署、資安、權限、測試和維護。」
「AI 做出來的東西有點不對，但我不知道怎麼修。」
開悟之坡

信心不再來自一次成功，而是來自方法、驗證與知道何時求助。

「我不需要追完每一個新工具。」
「我開始知道要先問：它解決什麼問題？」
「我做得出原型，但知道原型不等於產品。」
「我可以使用 AI，但不把判斷責任交給 AI。」
平穩高原

AI 不再是魔法，而是可以穩定使用、評估與管理的工具之一。

「我知道什麼時候該用 AI，也知道什麼時候不該用。」
「我能穩定設計、驗證、維護，也知道結果由誰負責。」
做小一點資料不要敏感結果要能人工檢查失敗要能回復 最簡單的開始方式：CDC 給的 Gemini Pro ＋ Canvas
AI 超充站　加快資訊吸收
AI 社團　交流問題、展示作品、互相校準

不要把未經核准的機密資料，直接丟給雲端 AI 模型。
